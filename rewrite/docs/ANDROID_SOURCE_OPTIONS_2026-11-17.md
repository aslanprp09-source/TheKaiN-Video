# Android: расширение поддержки видеосайтов — исследование 17.11.2026

Refs #5. Отдельный этап после завершения [PR #23](https://github.com/aslanprp09-source/TheKaiN-Video/pull/23), merge `541f86e555745c2126a296d09055b1515b5257fd` в `rebuild-2026-11-11`. Дополняет [исследование M5](M5_SOURCE_RESEARCH.md). Это проверка актуальных исходников и документации; новые зависимости, исполняемые файлы и сетевые экстракторы не установлены и не запущены. Совместимость кандидатов с TheKaiN пока не доказана.

## Вывод и рекомендуемое направление

Для широкой поддержки сайтов предпочтительный кандидат для **изолированного прототипа** — актуальный yt-dlp с отдельно проверенным Android-runtime. Готовая старая Android-обёртка не даёт достаточных доказательств совместимости с сегодняшним Python/EJS. Для более узкого набора сервисов стоит сравнить NewPipeExtractor: он убирает необходимость Python/native-пакета, но сохраняет JavaScript-интерпретацию, GPL и необходимость адаптации сети/форматов.

Включать любой из этих вариантов в приложение сейчас преждевременно: не закрыты лицензия распространения приложения, происхождение конкретных runtime-бинарников, Android 8+/ABI/16 КиБ, ограничения процессов и контракт передачи потоков. Следующий PR должен проверять один кандидат на разрешённых фикстурах, с выключенной по умолчанию интеграцией; решение о включении — после результатов и независимого ревью. Сервер обработки ссылок не входит в MVP и требует отдельного решения по приватности.

## Что объясняют результаты владельца

Samsung Galaxy S24 Ultra, Android 17 / One UI 9.0: интерфейс работает, прямая MP4-ссылка анализируется и скачивается; YouTube сообщает «Страница слишком большая для безопасного анализа»; страница `lord-of-the-rings.ru` не отвечает. Точная установленная сборка и её хеш неизвестны. Это наблюдения владельца, а не проверка новых адаптеров или удаления в PR #23.

На исходниках merge PR #23 [HttpsSourceAnalyzer](../android/app/src/main/java/com/thekain/video/source/HttpsSourceAnalyzer.kt) ограничивает HTML **512 КиБ**, проверяя и Content-Length, и фактически прочитанные байты; общий срок анализа — максимум **30 секунд**, включая редиректы и пробы файлов. Он извлекает статические `video/audio/source`, допускает максимум восемь кандидатов и не исполняет JavaScript. Ошибка YouTube согласуется с этим лимитом; точный ответ телефона не захвачен. Поднять лимит недостаточно для поддержки YouTube, а ограничение памяти и времени необходимо сохранить.

Для `https://lord-of-the-rings.ru/episodes/3-season-1-seriya/` причина не установлена: нужны код ошибки, точная сборка и безопасная диагностика этапа DNS/TLS/HTTP/таймаута. Нет доказательства общего сбоя сайта. В изученном списке yt-dlp нет отдельного имени этого домена, но generic/embed extraction иногда обслуживает неназванные сайты: отсутствие имени не доказывает ни поддержку, ни её невозможность. Скачивание содержимого этой страницы в исследование не входило; права на него не предполагаются.

### yt-dlp: runtime, обновления и безопасность

[README на исследованном SHA](https://github.com/yt-dlp/yt-dlp/blob/8f9e23a47eb68816a639096aecfb9d802f83c0a5/README.md) прямо различает лицензии wheel и standalone-бандлов. EJS — Unlicense с включёнными MIT/ISC-компонентами; поддерживаются Deno, Node, Bun, QuickJS, рекомендован Deno. Их Android-бинарники, минимальные версии, дополнительные лицензии, память и завершение процессов надо проверить отдельно. Desktop/Linux executable не является Android-бинарником лишь потому, что CPU arm64.

Stable release notes сообщают об исправлениях уязвимостей brotli/certifi/curl-cffi в официальных executables. Это требует проверки реальных транзитивных зависимостей выбранного Android-пакета, а не объявления любого wheel/AAR безопасным по номеру yt-dlp. Аудит известных advisories и происхождения должен повторяться на конкретном pin перед сборкой.

Upstream публикует SHA256/SHA512 и GPG-подписи; будущая сборка должна проверять pin и доверенный ключ для выбранного формата либо воспроизводимо собирать из проверенных источников. В этом исследовании такие бинарники не скачивались и их подписи не проверялись. Новые runtime/adapter версии предпочтительно доставлять через проверенную подписанную сборку приложения; не включать `--update`, remote EJS fetching или плагины из сети. Site fixes могут требовать более нового master/nightly, но это повод для отдельного pin и тестов, а не автоматического доверия каналу.

У старой обёртки [Updater](https://github.com/yausername/youtubedl-android/blob/d725d5c9a18c3a99a13ee0308bf78275dc310760/library/src/main/java/com/yausername/youtubedl_android/YoutubeDLUpdater.kt) получает URL релиза и копирует файл без отдельной проверки digest/signature в этом коде. [YoutubeDL.kt](https://github.com/yausername/youtubedl-android/blob/d725d5c9a18c3a99a13ee0308bf78275dc310760/library/src/main/java/com/yausername/youtubedl_android/YoutubeDL.kt) запускает `libpython.so` из nativeLibraryDir через ProcessBuilder; helper уничтожения процесса использует `/system/bin/sh -c`. В будущей интеграции запретить пользовательские аргументы/конфиги/пути, генерировать внутренний проверенный process ID и завершать дерево процессов без интерполяции URL в shell. Это результаты чтения кода, не демонстрация эксплуатации.

Дополнительный современный источник — [ytdlnis-packages, SHA e14f05ea40bd9f7a5d25c2eda6bb69b9d597b5da](https://github.com/deniscerri/ytdlnis-packages/tree/e14f05ea40bd9f7a5d25c2eda6bb69b9d597b5da) от 11.11; release Python 3.14.8 опубликован 07.11. Его README описывает helper APK/native executables и **локально собранные, вручную опубликованные** пакеты. Утверждения README об ограничениях Android/target SDK не являются проверкой платформы. Не снижать targetSdk, не устанавливать дополнительные APK и не заимствовать такой механизм без проверки signer identity, происхождения, воспроизводимости и поведения на текущем Android. Это более свежий путь исследования, но пока не доверенный runtime для TheKaiN.

### NewPipeExtractor: что дополнительно проверить

[Root build](https://github.com/TeamNewPipe/NewPipeExtractor/blob/6ce85c1af05bbb854bae73f8936fd9f75bb8f9e1/build.gradle.kts) использует Java toolchain 17; checkstyle upstream отдельно требует JDK21. Это настройки сборки, не доказательство минимальной Android-версии готового JAR. [Version catalog](https://github.com/TeamNewPipe/NewPipeExtractor/blob/6ce85c1af05bbb854bae73f8936fd9f75bb8f9e1/gradle/libs.versions.toml) содержит Rhino 1.8.1, jsoup 1.24.1, protobuf-javalite 4.36.2 и nanojson по commit pin: необходимо проверить конфликт с текущим jsoup, bytecode/desugaring, transitive notices и R8 release. Это исследованные upstream-версии, не изменения зависимостей приложения.

[Downloader.execute(Request)](https://github.com/TeamNewPipe/NewPipeExtractor/blob/6ce85c1af05bbb854bae73f8936fd9f75bb8f9e1/extractor/src/main/java/org/schabi/newpipe/extractor/downloader/Downloader.java) реализует клиент. Можно централизовать HTTPS/редиректы/таймауты/размеры/отмену в нашем адаптере, но поддерживаемость сервисов после таких ограничений надо проверить. CAPTCHA, private/auth, DRM и геоограничения должны завершаться явной ошибкой; не переносить обходы ограничений из upstream автоматически. Декларация поддержки сервиса не гарантирует доступность конкретного ролика, региона или сети.

## Контракт интеграции и ограничения

Текущий [MediaVariant](../android/app/src/main/java/com/thekain/video/source/Sources.kt) содержит один DirectRequest и размер, а не произвольный план скачивания. Поэтому JSON с форматами нельзя просто подать UI как готовую поддержку сайта. Новый адаптер должен описать реальные дорожки, контейнер, требуемые безопасные headers, срок жизни URL, `requiresMerge`, manifest/DRM/unsupported reason. Не показывать неподдерживаемые варианты как скачиваемые; не выдавать высокий resolution без аудио за готовое видео со звуком.

Для первого прототипа ограничить результат одиночным HTTPS-файлом с поддерживаемым контейнером и необходимыми дорожками; HLS/DASH, отдельные дорожки и FFmpeg — отдельный этап с verifier/postprocessing. Повторный анализ истёкшего URL не должен молча подменять выбранный формат. Заголовки и signed URL не попадают в логи; cookies/account/netrc/browser import, пользовательские plugins/config и посторонние команды запрещены. Для yt-dlp использовать фиксированный аргументный вектор или строгие параметры API, отключить загрузку media при анализе, плейлисты и внешние конфиги. Ограничения глубины embed/redirect, объёма JSON/stdout/stderr, времени и памяти должны действовать даже при зависшем дочернем процессе.

Любой результат проходит прежнюю очередь, UUID staging, проверку целого медиа и MediaStore/FileProvider; metadata success не равен COMPLETED. Сохранить безопасное удаление PR #23, восстановление и реальную отмену. Нельзя отдавать экстрактору произвольный публичный путь назначения или прямое удаление пользовательских файлов.

## Проверяемый следующий этап

1. **Лицензия и происхождение:** выбрать допустимую модель распространения нового Android-приложения, проверить GPL для NewPipe/обёртки и соответствующие исходники/уведомления всех компонентов. У yt-dlp wheel нет GPL самого экстрактора, но это не решает лицензии runtime/FFmpeg. Ничего не перелицензировать в archival main. Зафиксировать исходники, хеши и полный resolved inventory до упаковки.
2. **Изолированный runtime spike:** сравнить минимальный yt-dlp/Python/EJS bundle и NewPipe на собственных fixture-страницах, без изменения пользовательского production-пути. Собирать/проверять выбранные артефакты; не исполнять неизвестные скачанные бинарники. Отдельно измерить cold start, APK size, peak memory, отмену и очистку процессов.
3. **Android:** API 26 (FileProvider), 29 (MediaStore), 35 и актуальная доступная версия; все поставляемые ABI, минимум arm64 и CI x86_64. Проверить ELF/ZIP alignment и реальное исполнение **на 16 КиБ**, а не только флаг сборки. Затем точная подписанная QA-сборка на S24 Ultra, с хешем и версией; подпись только через защищённый release-signing и независимое ревью. Новая сборка здесь не запрашивалась.
4. **Сеть и медиаданные:** собственные/явно лицензированные live fixtures с согласованными URL; redirects, oversized/infinite response, timeout/cancel, 403/404/429/expiry, unknown sizes, malformed JSON, no formats/audio-only/separate tracks, DRM/auth/geo refusal, restart, disk-full, corrupt media и сохранность других файлов. Фиксировать site/date/adapter/runtime/device; не считать офлайн фикстуру доказательством живого YouTube.
5. **Решение о включении:** отдельный PR к rebuild, реальные результаты CI/лицензий/runtime, независимый approval на точном HEAD. Не менять main/защиты, не публиковать приложение. `production_ready=false`, `automatic_publication=false`; Issue #6 остаётся открытой.

## Пределы выполненной проверки

Выполнено чтение текущего кода TheKaiN и первичных GitHub release/source/license/build данных кандидатов.
