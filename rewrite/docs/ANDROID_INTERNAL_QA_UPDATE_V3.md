Refs #6. Подготовка после PR #23; не публичный релиз. Новая идентичность APK: `com.thekain.video.rebuild`, `versionCode=3`, `versionName=0.1.0-m6`, minSdk 26. Сохраняется имя версии M6 и имя файла в существующем packaging-контракте; различать артефакты нужно по run ID, source commit, versionCode и SHA-256, а не одному имени APK. Room schema, application ID, FileProvider authority и зависимости не меняются этим PR.

## Порядок сборки и допуска к установке

1. Независимый KaiN1One review на точном HEAD этого PR, все четыре строгие проверки CI и дополнительные API 26/29. Объединение обычным PR в `rebuild-2026-11-11`, без обхода правил. Исследовательский PR #25 рассматривается отдельно.
2. На текущем проверенном tip rebuild запустить существующий `rewrite-ci.yml` через workflow_dispatch с `build_packages=true`, `sign_android=true`, `verify_artifact=false`. Убедиться, что run использует нужный SHA. Старые действия публикации/релизов не запускать. Если ветка изменится, policy требует актуальный tip; не обходить отказ и не переносить артефакты между запусками.
3. Сборка без ключа, CI и signing rehearsal с одноразовым тестовым ключом должны пройти. Настоящая подпись разрешена только существующим Environment `release-signing` с отдельным одобрением KaiN1One; ключ/пароли остаются там. Protected signing проверяет same-run digests и branch/environment policy до получения ключевого материала.
4. В `M6-Android-signed-INTERNAL-QA` проверить `inspection.json`, `manifest.json`, `SHA256SUMS`, source commit, `signed=true`, `debuggable=false`, application ID и **versionCode 3**. APK должен успешно пройти официальный `apksigner verify --verbose --print-certs` и иметь ожидаемый сертификат SHA-256:

   `2E8FBB21ADB81873D257FF685E904B710F7E63DF4C9EA207C6BF2C0B27CB973E`

   Это публичный fingerprint прежней подписанной QA-сборки (run 69), не секрет. Проверить также контрольную сумму самого скачанного APK. Нельзя считать filename или успешную загрузку доказательством подписи. AAB не устанавливать на телефон напрямую.
5. Старый independent-verifier workflow закреплён на оригинальном артефакте run 69/versionCode 2: его PASS **не проверяет новую сборку**. Не менять его исторические pins ради нового теста. Дополнительная независимая проверка нового APK должна явно указывать новый run/artifact/hash и проверять подпись официальным SDK, без пересылки ключей. Здесь новые хеши/результаты ещё не объявлены.

## На основном Samsung Galaxy S24 Ultra

Android 17 / One UI 9.0 — данные владельца. До начала записать версию установленного приложения, число записей, состояния задач и наличие файлов. Сначала дождаться завершения активных задач. Для удаления использовать **новые собственные тестовые копии**, не единственные экземпляры ценных видео. Сохранить резервную копию важных файлов обычным способом телефона.

Установить только проверенный подписанный **APK обновлением поверх** существующего `com.thekain.video.rebuild`: подтвердить «Обновить». Не удалять приложение, не очищать его данные, не устанавливать debug/differently-signed APK и не использовать downgrade/обход проверки пакета. Если Android отказывает в обновлении или предлагает отдельное приложение вместо ожидаемого обновления, остановиться и зафиксировать точный текст ошибки. Известный сертификат старого артефакта не доказывает, что именно он сейчас установлен на телефоне; успех обновления и сохранность данных нужно подтвердить на устройстве.

После установки проверить сохранность прежней библиотеки/настроек, открыть один сохранённый файл и записать точную новую сборку: run ID, commit, versionCode 3, APK SHA-256. Затем создать три собственные короткие загрузки A/B/C с разными UUID и провести проверки:

| Проверка | Ожидаемый результат |
|---|---|
| В «Загрузках» открыть удаление A и выбрать «Отмена» | Запись и файл остаются, библиотека согласована. |
| Удалить A только из списка | Запись исчезает из загрузок/библиотеки; опубликованный файл доступен в файловом менеджере и воспроизводится. Его приватные рабочие копии могут быть очищены. |
| В «Библиотеке» удалить B вместе с файлом | Подтверждённо исчезают запись и принадлежащий ей опубликованный файл; уведомление не появляется заново. |
| Быстро повторно нажать действие удаления | Во время операции кнопки отключены, нет повторной операции, зависания или ложного успеха. |
| Проверить C и прежние видео | Все нетронутые записи/файлы сохранены и воспроизводятся. Повторить оба режима в другой вкладке на новых копиях. |
| На новой тестовой копии удалить файл файловым менеджером, затем повторить удаление в приложении | Нет падения; уже отсутствующий собственный файл обрабатывается безопасно, чужие файлы не затронуты. |
| Закрыть и снова открыть приложение | Состояние библиотеки сохраняется, удалённые записи/уведомления не возвращаются. |

Нельзя прерывать обновление ради проверки аварийного сценария на ценных данных. При ошибке удаления не обещать сохранность файла: он мог исчезнуть до более поздней ошибки БД/очистки. Проверить фактическое наличие файла и сохранить запись результата до повторения.

## Что записывать в отчёт

Для каждого случая: вкладка/действие, ожидаемый и фактический результат, запись/файл до и после, версия ОС, build/run/hash; скриншот ошибки при наличии. Не отправлять cookies, ключи, URL с секретными query-параметрами или посторонние личные файлы. Без фактического выполнения не отмечать upgrade или Samsung QA как PASS.

Проверка нового удаления не добавляет поддержку YouTube/других динамических видеосайтов. `production_ready=false`, `automatic_publication=false`; Issue #6 остаётся открытой, публикации нет.
